# Оптимизация обработки выписок

Запуск: `.venv/bin/python main.py [путь_к_PDF]`.
По умолчанию обрабатывается `spravka_vtb.pdf`. Проверка `res_clean.txt`
и подтверждение перед передачей данных остаются обязательными.

- Повторяющиеся строки входа кодируются ссылками на словарь. Текст,
  порядок строк, суммы и повторы операций сохраняются. Если выигрыш
  меньше 10% символов, передаётся исходный текст.
- Модель возвращает JSON со справочниками дат и троек
  «описание, валюта, категория», а операции ссылаются на них индексами.
  Python восстанавливает CSV с прежними пятью колонками и UTF-8 BOM.
  Денежные значения остаются строками, без округления через float.
- Проверенные ответы сохраняются в `.llm_cache`. Повтор идентичного
  запроса использует сохранённый результат без обращения к API.
  Ключ учитывает вход, инструкции, модель, адрес сервиса и версию протокола.
  `--no-cache` отключает чтение и запись кэша.
- Неполный ответ, неверный JSON или ошибочные ссылки не перезаписывают
  `result.csv`. Запись результата атомарная.
- В консоли выводятся время вызова и токены из `usage`, если сервер
  их предоставляет. Число символов не является числом токенов.

Модель: `gemini-3.8-flash`, сервер: `https://ai.starimg.ru/v1`.
Используется библиотека OpenAI и прежний `API_KEY` из `.env`.
Параметры reasoning и лимиты генерации не урезаны.
Рекомендация сокращать объём генерируемого текста:
https://developers.openai.com/api/docs/guides/latency-optimization
Совместимость дополнительных параметров этого стороннего сервера не предполагается.

Локальная проверка на существующем `result.csv`: 65 операций,
4484 символа CSV → 2180 символов компактного JSON (−51,4%).
Обратное преобразование сохранило все ячейки операций. Это измерение
представления данных, а не реального ответа модели или токенов API.

Тесты: `.venv/bin/python -m unittest -v test_personal_data test_llm_pipeline`.
Проверяются точность сумм, дубликаты, кавычки и переносы строк, обратимость
упаковки, проверка ответа, кэш и его инвалидирование.

Сохранность данных при кодировании проверяется локально. Совпадение
нового вывода LLM со старым (особенно описаний и категорий) и фактическое
ускорение требуют сравнения вызовов API на проверенных обезличенных данных.
Изменение формата запроса не даёт гарантии идентичного поведения модели.
При попадании в кэш возвращается тот же сохранённый результат.
