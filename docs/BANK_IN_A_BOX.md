# Проверка Bank-in-a-Box

Источник: https://github.com/GalkinTech/bank-in-a-box
Версия: `ffa454577b61d861738635d3078723c93e7429da`.
Полная копия с MIT-лицензией находится в `infra/bank/upstream`.
Статья https://habr.com/ru/companies/vtb/articles/985546/ использована для контекста;
контракт адаптера проверен по исходникам, а не по статье.

| Возможность | Подтверждение в исходниках | Использование |
|---|---|---|
| Локальная БД | `database.py`, `models.py`, `docker-compose.yml` | PostgreSQL 15, отдельная от SQLite приложения |
| Вход клиента | `api/auth.py:31`, POST `/auth/login`, JSON username/password | Только backend, тестовый demo-student |
| Счета | `api/accounts.py:25`, GET `/accounts` | `data.account`, accountId, currency, nickname |
| Балансы | `api/accounts.py:224`, GET `/accounts/{id}/balances` | `data.balance`, InterimBooked, amount.amount/currency, dateTime |
| История | `api/accounts.py:297`, GET `/accounts/{id}/transactions` | `data.transaction`, page, limit=100, meta.totalPages |
| Данные операции | Те же элементы истории с transactionId | Отдельного GET одной транзакции нет; не выдумываем маршрут |
| Платёж | `api/payments.py:77`, POST `/payments`; GET `/payments/{payment_id}` | Исследовано, не вызывается приложением |
| Межбанковский перевод | `api/interbank.py`, `/interbank/receive` | Приём перевода, не webhook истории; не используется |
| Карты | `api/cards.py` | Выпуск, статус, лимиты, чтение; метода карточной покупки нет |
| Согласия | `api/consents.py`, `/account-consents/request`, sign, authorize | Межбанковский доступ через x-consent-id и x-requesting-bank |
| Новые операции | В маршрутах нет webhook подписки на историю | Polling 15 секунд + собственный SSE приложения |

Вход `/auth/login` помечен upstream как внутренний UI-метод, скрыт из OpenAPI.
Используется только для локального учебного стенда; это не production OAuth
и не разрешение на доступ к реальным банковским счетам.
В `/openapi.json` можно проверить остальные маршруты после запуска.

## Обнаруженные ограничения

* Смешаны абсолютные и относительные импорты в accounts/cards; штатный main
  не импортируется. Наш `launch.py` создаёт временную копию и исправляет только
  эти импорты и отсутствующий require_client в product_agreement_consents. Исходная копия и банковская бизнес-логика не изменяются.
* Старый init.sql не совпадает с текущими ORM-моделями. Используем создание
  таблиц по models.py и отдельный идемпотентный seed синтетического клиента.
* Фильтры from/to в истории фактически TODO. Адаптер перечитывает страницы,
  чтобы обнаружить старые операции с новым статусом. Лимит 100 страниц:
  превышение — ошибка без частичной фиксации.
* История и баланс не выдаются атомарным snapshot. Сначала читаем историю,
  затем проведённый баланс; операции, уже включённые в него, не вычитаются
  повторно. Возможна краткая несогласованность при параллельных внешних записях,
  устраняемая следующим polling. Наш адаптер не создаёт банковские платежи.
* Часть detail-маршрутов upstream неполно проверяет владельца счёта. Адаптер
  разрешает только ID, полученные от `/accounts` данного клиента; frontend не
  может передать произвольный банковский ID или URL.
* Вызов check_consent в accounts передаёт consent_id, которого нет в сигнатуре
  текущего ConsentService. Федерация также требует registry, JWKS, credentials
  участников и других банков. Историческая HackAPI не нужна для своего клиента;
  работоспособность межбанковского контура этим MVP не заявляется.
* Upstream имеет учебные пароли и открытые admin-маршруты. Порт привязан только
  к 127.0.0.1; стенд нельзя публиковать в интернете.
* `refunded` у исходного дебета трактуется как отмена его влияния; отдельная
  кредитная операция с Refund/«возврат» — как уменьшение расходов. Неизвестные
  статусы не входят в проведённые расходы. Generic IssuedDebitTransfer не
  считается автоматически переводом между своими счетами.

## Синтетические покупки

`DemoTransactionConnector` записывает только в SQLite приложения и имеет
отдельные sim-main/sim-save. Источник в UI — «Симулятор». Bank-in-a-Box не
получает фиктивные карточные вызовы, его баланс при этих покупках не меняется.
В общем демопрофиле суммируются независимые синтетические счета; банк можно
смотреть отдельно. Seed банка: 25 000 − 250 = 24 750 RUB на checking и
5 000 RUB на savings, обе истории согласованы с балансами.
